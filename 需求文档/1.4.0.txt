轻漫游 需求规格 1.4.0
从当前位置出发，接到附近一个点的真路
================================================

本文档是 **1.4.0**（里程碑）。继承 1.3.0 高德全栈 / GCJ-02 / 北京点位库，以及 1.3.5 的 5km 硬圆。
聊天闸门、限流、PWA、1.1.9 留缝布局、1.2.0 键盘可拖全部保留。
冲突时以本文件为准。完成后 git tag 必须是 **v1.4.0**。


0. 这一版解决什么
-----------------
1.3.x 已换成高德底图，但真机上仍会出现：iPhone 蓝点整体偏西、确认后看不见贴路折线、通州用户看到一串跨城编号点。

1.4.0 把「家门口短途」收成一句可验收的行为：

  定位必须是 GCJ-02，蓝点钉在真实道路/小区附近。
  生成后只显示 **一个** 附近目的地（5km 内）。
  路网从 **用户当前坐标** 接到该点，用高德步行/骑行真折线，确认后才上图。
  禁止一串 1～5 号途经点冒充路线；禁止没折线只丢钉子。


1. 定位（覆盖 1.3.0「不要再 gcj02→wgs84」的误读）
------------------------------------------------
底图、点位库、高德路径、「我」全部 **GCJ-02**。

iPhone Safari 的 `navigator.geolocation` 是 **WGS84**。直接画在高德上，点会整段偏西。
本版必须：浏览器 GPS → 转成 GCJ-02（高德 `convertFrom('gps')`，失败则本地转换）再画蓝点、再交给 `/api/plan`。
不要把未转换的 WGS84 当「我」。不要用会绕过转换的定位插件结果直接上图。

没有合法定位：不准规划。引导用户点定位。


2. 一条真路：原点 → 一个目的地
------------------------------
`/api/plan`：

  必须带 `near`（用户 GCJ-02）。
  从模型/点位库给出的名字里，只保留距 `near` ≤ 5000m 的点，取最近一个当目的地。
  只规划 **一段** 高德路：walk/trail 用步行，cycling 用骑行（骑行失败可降级步行，仍须是路网折线）。
  返回 `{ from, stops:[目的地], geometry:[[lat,lng],...], provider:"amap" }`。
  有效点不够或路网失败：中文提示，不出确认闸门。

前端：

  有 `from` 时地图只钉目的地一个编号，加上蓝点，加上 geometry 折线（须肉眼贴路）。
  未确认不得 `renderRoute`。
  示例路线仍可保留多点通惠河样本，不走 `/api/plan`。


3. 5 公里圆（继承 1.3.5 空间硬约束）
------------------------------------
有 GPS 时，点位库召回半径写死 5000m。圆外点不进候选、不上图。
通州圆心不得出现西城胡同。
1.3.0「按时长 × 步速估半径」在有定位时作废。

本版不把 `type=intent` JSON 甩给用户，也不要求单独渲染意图卡。对话仍是口语确认 + 最多两问。


4. 运行时
---------
生产函数区域：香港 `hkg1`（高德 Web 服务从美西会超时）。
底图：浏览器直连 `webapi.amap.com`（不要代理藏 JS Key 导致灰图）。
Key 只进 `.env` / Vercel Env，禁止进 Git。
