2. 安全设计（必须按此实现）
--------------------------
新增 Vercel Serverless：

  /api/health   GET   { ok: true, serverKey: boolean }
  /api/chat     POST  转发 DeepSeek Chat Completions

行为：

  A. 请求带 Authorization: Bearer sk-...（访客自己的 Key）
     → 用访客 Key 调 DeepSeek，忽略服务端 Key。
  B. 请求不带 Bearer，但 Vercel Env 有 DEEPSEEK_API_KEY
     → 用服务端 Key。这是公网 Demo 的主路径。
  C. 两者都没有 → 401，JSON { error: { message: "未配置模型 Key" } }

硬性禁止：

  - Key 写入代码、README、commit、前端常量
  - console.log / 响应里回显 Key 或 Authorization
  - 把整个 DeepSeek 报错原文里的 Key 传回浏览器（若有则打码）
  - 公共 CORS 代理
  - 把 DEEPSEEK_API_KEY 写进 vercel.json

限流（防把「藏 Key」变成免费代理）：

  - 只允许 POST JSON；body 上限约 200KB
  - max_tokens 服务端封顶 4096，模型白名单：deepseek-chat / deepseek-reasoner
  - 按 IP 粗限流：同一 IP 10 分钟内最多 20 次（内存 Map 即可，Demo 足够；实例重启清零可接受）
  - 超限 429

CORS：函数与静态站同源，不必对全世界开 *。若要预检，只允许本站 Origin。
