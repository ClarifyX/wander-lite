## 工作方式

1. **严格分四阶段提交可运行结果**。不要一上来接模型。阶段 1 能打开页面、拖地图、可安装；阶段 2 能加载示例路线；阶段 3 才接 DeepSeek；阶段 4 才谈部署文档。
2. **每一阶段结束时，对照 `10-验收清单.md` 对应条目自检**，未通过不要进入下一阶段。
3. 现有仓库里的 `js/agents.js`、`js/poi.js` 是旧的本地三 Agent，**不要当主路径**。主路径：PWA 壳 → 静态 JSON 验证 → DeepSeek Chat Completions（见 1.0.2）→ 人工闸门渲染。旧 `server.py` 只允许改成「不存 Key 的同源反代」，不要复活本地编排。
4. 可以删改旧文件，最终目录以 `03-技术架构.md` 的目标结构为准。保留有用的视觉感觉可以，但交互协议必须换成本文档。
5. **不要把任何 API Key 写进代码、HTML、示例、README、Git。** Key 只存在运行时内存。
6. **不要做长途旅行规划、登录系统、后端数据库、支付、原生 App。**
7. 产品文档（架构说明、README）在阶段 4 一并写进仓库。Figma 原型不在本实现任务内，代码里留产品文档链接位即可。
8. 中文 UI。代码注释少写，只在协议/闸门/JSON 解析等关键处写必要注释。
9. 本地用任意静态服务器即可（如 `python3 -m http.server 8787`）。不要引入打包器，除非你有充分理由；默认 **无构建步骤的静态站**。

## 完成定义

同时满足：

- 未填 Key 时：聊天可用示例按钮加载静态路线，地图能打点画线弹窗。
- 填了 DeepSeek Key 后：模糊一句话 → 追问 → JSON → 预览闸门 → 确认后地图渲染。
- PWA：Chrome/Edge 可安装；刷新离线至少能打开壳（地图瓦片允许在线）。
- README 写清：如何本地运行、如何部署 GitHub Pages、使用者须自备 DeepSeek API Key、CORS 与 `server.py`。
- `10-验收清单.md` 全部勾得上。

## 不要做的事

- 不要跳过人工闸门，让模型一返回就画地图。
- 不要用 `localStorage` / `sessionStorage` 存 API Key。
- 不要调用高德 / 谷歌 / Mapbox（要 Key 或绑卡）。
- 不要把模型全文原样展示成唯一结果；要抽出 JSON，失败要明确报错。
- 不要接 Claude / Anthropic。
- 不要做贴屏幕边的全宽抽屉。
- 不要一次追问超过 2 个问题。
- 不要发明阶段 2 之外的复杂后端。
