# 阶段 4：测试 + 部署分发

## 本地全流程测试（必须自己点一遍）

无 Key：

1. 打开 `http://127.0.0.1:8787`（或你用的端口），全屏地图 + 四周留缝抽屉，地图可拖可缩放。
2. 不填 Key 点发送，有友好提示。
3. 【加载示例路线】打点画线弹窗，重复点击不叠加。
4. Chrome 地址栏或「安装应用」能看到 PWA 安装（localhost 允许）。安装后独立窗口打开。

有 Key（需要你或用户提供，文档里不要写真实 Key）：

5. 填 Key，用示例 chip「老厂房骑行」走完：追问 → JSON → 预览（此时地图应仍是示例或空，取决于是否先点过示例）→ 确认 → 新路线覆盖上图。
6. 点重新生成，出现新预览，未确认前地图仍是上一条已确认结果。
7. 故意让模型说废话：若无 JSON，UI 报解析失败，地图不变。
8. 用户说「帮我订去成都玩三天」，模型应拒绝长途，不画图。

移动宽度：把窗口拉到 390px 宽，输入框仍能用，地图仍有高度。

## GitHub Pages

README 写清：

1. 推送到公开仓库
2. Settings → Pages → Deploy from branch → `main` → `/` (root)
3. 访问 `https://<user>.github.io/<repo>/`
4. **公开部署后，使用者必须自行填入 DeepSeek API Key 才能调用 AI**。无 Key 仍可加载示例路线、浏览地图。若浏览器 CORS 拦住 DeepSeek，按 README 用本地 `server.py`。

注意：

- 资源路径全部用相对路径 `./js/...`，不要写成 `/js/...`（GitHub Pages 在项目页会挂在子路径）。
- `manifest.start_url` 与 `scope` 用 `./`
- Service Worker 在子路径下也能控制本 repo scope
