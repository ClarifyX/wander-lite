# 技术架构

## 形态

纯静态 PWA。无必选后端。GitHub Pages 可直接托管。

使用者在页面填 DeepSeek API Key → 浏览器请求 DeepSeek Chat Completions（CORS 不通时走同源反代，见 `1.0.2.txt`）。

## 目标目录（实现完成后应接近此结构）

```
index.html
manifest.json
service-worker.js
css/app.css
js/app.js          状态机、聊天编排、闸门
js/sheet.js        Bottom Sheet 三档吸附（half / expanded / collapsed）
js/map.js          Leaflet 封装：打点、画线、弹窗、清空、按抽屉高度 padding
js/deepseek.js     调 DeepSeek、system prompt、消息历史
js/parse-route.js  正则抽 JSON、校验字段
data/sample-route.json
icons/icon-192.png
icons/icon-512.png
README.md
docs/产品架构.md   给人看的架构说明（阶段 4 写）
需求文档/          本文件夹，保留不要删
项目总结.txt
```

允许把小函数合并，但 **地图 / DeepSeek / JSON 解析 / 主状态机 / 抽屉** 不要揉成单文件超过合理阅读负担。禁止上 React/Vue/打包器，除非需求变更。

## 运行时数据流

```
用户输入
  → js/app.js 追加到 messages UI
  → 若无 Key：可走快捷【加载示例路线】（阶段 2）
  → 若有 Key：js/deepseek.js 发送 messages[]
  → 回复原文进聊天
  → js/parse-route.js 抽 JSON
       失败 → 错误提示，不画图
       成功 → 预览卡 + 闸门
  → 用户确认 → js/map.js render(route)
```

## 地图

- 库：Leaflet 1.9.x，CDN（unpkg 或 cdnjs），阶段 1 就要引入。
- 底图（1.0.1 强制）：CartoDB `light_all`
  `https://{s}.basemaps.cartocdn.com/light_all/{z}/{x}/{y}{r}.png`
  attribution：© OpenStreetMap © CARTO
- 默认中心：中国东部城市视野，建议 `[31.23, 121.47]`（上海）zoom 12。无路线时不要乱打点。
- 布局：地图 100vw×100vh；对话在四周留缝的悬浮 Bottom Sheet 里，**不要左右分栏、不要贴边全宽抽屉**。详见 `1.0.1.txt` + `1.0.2.txt`。
- 能力：拖拽、滚轮缩放、双击缩放、点位 Marker、Polyline、bindPopup。
- `fitBounds` / `invalidateSize` 必须加上当前抽屉高度的 bottom padding，路线不要被抽屉挡住。
- 禁止：地图商业 SDK；禁止 OSM 标准彩色瓦片当主底图。

## DeepSeek（1.0.2）

完整约定见 `1.0.2.txt`。摘要：

- Endpoint：`POST https://api.deepseek.com/chat/completions`（或同源 `/api/chat` 反代）
- Headers：`content-type: application/json`，`Authorization: Bearer <用户输入>`
- `model` 默认 `deepseek-chat`；`max_tokens` 4096
- `messages` 含一条 `system`（`02` 人设 + `08` 契约）+ 对话历史
- Key：内存变量，刷新丢失
- 失败：把 status 与 `error.message` 显示在对话里
- 禁止 Anthropic 请求头与 `api.anthropic.com`

## PWA

- `manifest.json`：`name` 轻漫游，`short_name` 轻漫游，`display: standalone`，`start_url: ./`，`scope: ./`，主题色与背景色与 UI 一致。
- `index.html` 引用 manifest，并设 `theme-color`。
- Service Worker：缓存 app shell（html/css/js/json/icons）。瓦片可以不缓存，或 cache-first 尽力而为。
- `index.html` 在 load 后 `navigator.serviceWorker.register('./service-worker.js')`。
- 图标：至少 192 与 512。浅灰底 + 简单路径图标，不要用未授权商标。
- `theme_color` / `background_color` 用浅灰（如 `#f2f2f7`），不要苔绿。

## 安全与作品集诚实边界

1. 前端带 Key 调用模型，Key 会进入用户自己的浏览器网络面板。这是 Demo 取舍，README 写明：仅供个人试用，不要在公共电脑保存页面。
2. GitHub Pages 不能替用户保密 Key，所以 **禁止服务端写死 Key**。
3. 路线真实性：阶段 3 依赖模型，阶段 2 用人工写死的真实点位做对照。产品文档里写：幻觉靠闸门 + 解析校验兜底，不靠模型自觉。

## 旧仓库对照（避免实现走偏）

| 旧实现 | 本需求 |
| --- | --- |
| 本地三 Agent + POI 知识库默认可跑 | 无 Key 时只保证壳 + 示例路线 |
| 本地三 Agent + 设置里开 DeepSeek | 对话主路径走 DeepSeek Chat Completions；`server.py` 仅作不存 Key 的 CORS 反代 |
| 设置弹窗开关 LLM | 页面上的 Key 输入（可折叠） |
| 接受/驳回改偏好 | 明确的【确认】【重新生成】按钮 |
| 无 PWA | 必须有 manifest + SW |

不要为了「兼容旧代码」保留两套主路径。最多把示例路线按钮留作无 Key 降级。
