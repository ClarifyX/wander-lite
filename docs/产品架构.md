# 产品架构：轻漫游

## 背景

年轻人在自己城市附近想找一条松弛、人少、有氛围的短途，往往说得出感觉、说不出地点。旅游 App 把供给推到网红点和远途；地图 App 假设你已经知道去哪。轻漫游只做家门口 1～3 小时：老街区漫步、城市骑行、公园轻越野。

不做长途，是因为一做跨城/多日，主交互就会退回天数、交通、酒店表单，对话挖掘就不再是产品核心。

## 用户流程

1. 打开即是全屏浅灰地图，对话在四周留缝的悬浮抽屉里（半高 / 几乎全屏但仍能瞥见地图边框 / 只剩输入条）。
2. 用户说一句模糊想法。Agent 追问，一次最多两问，补齐城市、方式、时长、起点片区。
3. 模型输出约定 JSON。前端抽出并做预览卡。
4. 人点【确认并画到地图】才渲染；【重新生成】或继续改话。
5. 地图打点、连线、点击介绍。抽屉降回半高，让路线露出来。

## 槽位与闸门

核心槽位：城市、出行方式、时长、起点。不齐禁止出路线 JSON。

闸门放在「有合法 JSON 初稿之后」：再早会变成表单，再晚会把幻觉路线直接当出行方案。

AI 负责抽约束、追问、编排点位。人负责生活事实（从哪出发）和出不出发的决策。

## 四阶段验证

1. **壳**：PWA + 全屏 Carto 浅灰地图 + 可拖 Bottom Sheet，无 LLM、无点位。
2. **静态图**：内置杨浦滨江示例 JSON，验证打点画线弹窗。
3. **DeepSeek**：Vercel Edge `/api/chat` 持有 Env 中的 Key；访客也可选填自己的 Key。确认闸门后才上图。
4. **分发**：GitHub + Vercel；tag 与需求文档版本号对齐。

这样面试时能讲清：先证明地图协议，再证明模型可替换，产品契约不变。

## 地图选型

Leaflet + CartoDB Positron（`light_all`）。个人作品集无 Key、无绑卡。不选高德 iframe（自定义弱），不选 Google / Mapbox（要注册账单）。交互上参考苹果地图的抽屉，而不是左右分栏聊天室。

## 风险与取舍

- **幻觉**：地点可能不存在。产品侧用解析校验 + 人工预览闸门兜底，不靠模型自觉。阶段 2 的写死点位是对照物。
- **Key 在浏览器**：Demo 取舍。README 写明仅供个人试用，刷新即丢，禁止写进仓库。
- **POI 不是全城索引**：真实产品需要供给中台；本 Demo 验证的是模糊需求下的对话协议。
- **为什么不用表单**：用户说不清参数。表单会假装需求已经结构化。

## 人机分工

| AI | 人 |
| --- | --- |
| 从自然语言抽槽位 | 确认起点这种生活事实 |
| 克制追问 | 决定走不走 |
| 输出地图可用 JSON | 点确认或重新生成 |
